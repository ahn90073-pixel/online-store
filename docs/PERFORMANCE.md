# استقرار تطبيق سوق اون لين

## ما تم تطبيقه

- **شاشة بدء مزدوجة:** شاشة Android الأصلية تظهر قبل WebView، ثم شاشة React باسم «سوق اون لين» لمدة قصيرة. لا تتجاوز الشاشة 2.6 ثانية؛ إذا تأخرت الشبكة لا يظل المستخدم محجوباً بلا نهاية.
- **تحميل صفحات:** يبدأ المتجر بصفحة من 40 منتجاً فقط، ثم يجلب الصفحة التالية عند الاقتراب من نهاية الشاشة أو بالزر اليدوي. هذا يمنع جلب عشرات الصفحات دفعة واحدة.
- **إلغاء الطلبات:** كل طلب جلب يملك `AbortController`؛ عند التحديث أو إعادة المحاولة يُلغى الطلب السابق ولا تُكتب نتيجته فوق الحالة الجديدة.
- **بحث مؤجل:** البحث ينتظر 220ms بعد آخر تغيير قبل تنفيذ الفلترة، مع فهرسة نصية مؤقتة لكل عملية `useMemo` بدلاً من تكرار التحويل أثناء الرسم.
- **صور اقتصادية:** الصور خارج الشاشة `lazy` و`decoding="async"` مع منع تحميل أولوية مرتفعة للبطاقات. يتم إخفاء الصورة التالفة بدلاً من إسقاط الواجهة.
- **التخزين المحلي:** SQLite يحفظ آخر صفحة ناجحة فقط بشكل ذري؛ تظهر النسخة المحلية فوراً ثم تُحدّث من الشبكة. أخطاء SQLite لا تغلق التطبيق.
- **تحمل الأعطال:** Error Boundary يعرض واجهة استرداد، وطلبات الشبكة والجسر الأصلي محاطة بمعالجة أخطاء، مع عدم إظهار رسائل تقنية للمستخدم.

## فحص الضغط

```bash
npm ci
npm run lint
npm run typecheck
npm run build
npx cap sync android
```

على جهاز Android، راقب الذاكرة والـ ANR من Android Studio Profiler أثناء:

1. تمرير آلاف المنتجات صعوداً وهبوطاً.
2. البحث المتواصل مع تغيير النص سريعاً.
3. فصل الشبكة ثم إعادة الاتصال والسحب للتحديث.
4. فتح معرض الصور وإغلاقه، ثم تدوير الشاشة وإرسال التطبيق للخلفية.

لا تحتفظ بمراجع `Activity` أو `View` داخل كائنات Singleton. في Java/Kotlin استخدم `applicationContext` للخدمات طويلة العمر، واربط أي Listener بدورة حياة الشاشة وأزله في `onDestroy`/`onStop`. في React أزل كل `timer` و`event listener` وألغِ الطلبات في cleanup كما هو موضح في `App.jsx`.
